; Agilent / Keysight E364xA Series DC Power Supplies - TestController driver
;
; Coverage   All ten E364x models: the six single-output, dual-range E3640A-
;            E3645A (30/50/80 W) and the four dual-output, dual-range E3646A-
;            E3649A (60/100 W) - one file, one #idString per model, exactly
;            one branch surviving per model after TestController's
;            #sections/#metaSection expansion. Dual models add a second
;            independent output and a voltage/range Track toggle; everything
;            else - both output ranges, voltage and current setpoints, Fine
;            Adjust, overvoltage protection with a trip indicator, bus and
;            immediate triggering, front-panel display text, five stored
;            states, and a CC/CV regulation readout - is common to both.
;            There is no overcurrent protection on any model - the family has
;            no CURR:PROT.
;

;            GPIB and RS-232, page by page, error queue clean throughout.
;            DUAL branch against a live E3648A (F/W 1.7-5.0-1.0) over both
;            GPIB and RS-232, both outputs run into an electronic load. Range
;            ceilings and finest step were read back from each instrument
;            rather than taken from the data sheet. The other eight models
;            carry manual-derived range and step figures and still need

#metaSection DUAL
; Readout is declared alongside PS/PS:2 on purpose: setReadoutString below is
; implemented, but PopupRemoteReadout filters on the interface type, so without
; Readout here a dual-output unit could never appear in the Remote Readout
; popup even though the command works. Same defect HP_Agilent_E363xA.txt fixed
; at rev 1.8; carried over rather than rediscovered.
#interfaceType PS PS:2 Readout

; INST:SEL is re-sent before each output's bare VOLT?/CURR?/MEAS queries: the
; query text is identical for both outputs, and the intervening INST:SEL write
; is what flushes TestController's per-read reply cache so output 2 does not
; get served output 1's answer. Do not group the queries or hoist INST:SEL out.
#askValues [mode:Log_All,Log_V_and_I_only]INST:SEL OUT1;[100];MEAS:VOLT?;[20];MEAS:CURR?;[20];INST:SEL OUT2;[100];MEAS:VOLT?;[20];MEAS:CURR?;[20];[mode:Log_All]INST:SEL OUT1;[100];VOLT?;[20];CURR?;[20];INST:SEL OUT2;[100];VOLT?;[20];CURR?;[20];STAT:QUES:INST:ISUM1:COND?;[20];STAT:QUES:INST:ISUM2:COND?;[20];[mode:]
#value Voltage V D4 Log_All,Log_V_and_I_only
#value Current A D4 Log_All,Log_V_and_I_only

; Shared: output enable. Instrument-wide on dual models (no per-output enable);
; the only output there is on a single-output model, so the same command and
; control serves both without gating.
#cmdSetup toggleButton Output
:read: [20];OUTP?
:write: OUTP (value)
:updatedelayed: 0.2
:updatealloff:
:color: gray green
:tip: Enable or disable the DC output. On dual-output models this is INSTRUMENT-WIDE - it turns Output 1 and Output 2 on or off together, since there is no per-output enable. Switch it ON yourself before an Auto Adjust or Param Sweeper run on a dual-output model: with two channels declared, DeviceInterface.setDeviceOn returns early, so those tools leave the output off and a sweep writes setpoints into a dead supply while looking like it worked.
OUTPUT_OFF 0
OUTPUT_ON 1

1 100 Sunken

; Everything down to the Settings View combobox carries NO page argument, on
; purpose - like HP_Agilent_E364xA.txt, the primary controls (range/voltage/
; current, and on a dual model both outputs plus Track) sit on the base Setup
; form ABOVE the tab strip, always visible, right under the Output toggle they
; belong with. Only Memory / Front Panel below are on the BasicSetup
; tab, further down. File order matters here: TestController renders page-less
; controls top-to-bottom in the order they appear, and a page-less control
; placed after the selector's own #cmdSetup line renders below the WHOLE
; tabbed panel, not above it or inside it - that misplacement (this block used
; to sit after the selector) is what made Output 1/2 "sink to the bottom" of
; the dialog, disconnected from the Output toggle at the top.

#metaSection DUAL
; Track sits with the global controls, not inside either output's own block -
; it is a relationship between the two outputs, not a property of one of them,
; and keeping it out of "Output 2" is what makes Output 1 and Output 2 read as
; the same shape (Range/Voltage/Current/Mode, nothing extra on either side).
#cmdSetup toggleButton Track
:read: [20];OUTP:TRAC?
:write: OUTP:TRAC (value)
:updatedelayed: 0.2
:color: gray green
:update: O2_Voltage O2_Range
:tip: Track Output 2 to Output 1. Confirmed on the front panel (operator, 2026-09-04): with this on, Output 2 matches Output 1 on BOTH voltage setpoint and range, not just voltage - the two outputs end up on the same range while tracking. Turn it off to set Output 2 independently again.
Off 0
On 1

; OUTP:REL is deliberately NOT exposed - carried over from the decision already
; made in HP_Agilent_E363xA.txt, which omits it for the same reason. It drives
; two TTL signals on RS-232 connector pins 1 and 9, and the E3640A-E3649A guide
; states, twice (p.54 and p.85): "Do not use the RS-232 interface if you have
; configured the power supply to output relay control signals. Internal
; components on the RS-232 circuitry may be damaged." A driver that offers this
; family over comFixedBaud must not also offer a one-click control that makes
; that configuration live. (The TTL output needs internal jumpers JP102/JP103
; fitted to do anything, so on an unmodified unit the button would be inert -
; but the driver cannot know which units are jumpered, and the failure mode is
; damage to the interface we are talking over.) Query it by hand if needed.
