; The supply returns one response per query. TestController sends semicolon-separated
; #askValues entries as independent commands, matching the live GPIB validation.
;
; Five channels are logged rather than the obvious two, because a test cannot
; usually be re-run to recover a value nobody thought to record:
;
;   Voltage / Current       what the terminals are actually doing (MEAS:)
;   VoltageSet / CurrentSet what the supply was asked for (VOLT? / CURR?)
;   Regulation              which side the supply is regulating on
;
; Charting the measured value against its setpoint shows the output sagging away
; from the demand under load, which neither one alone reveals. Regulation catches
; the moment a load pulls the supply out of constant voltage into constant
; current - usually the point of the test, and invisible from voltage and current
; alone when the limit happens to sit where the load settles. It is logged as the
; raw register value so it charts as steps:
;     0 = output off or unregulated   1 = constant current
;     2 = constant voltage            3 = regulation fault
; The bits are not latched, so this is the live state at each reading.
;
; The cost is five GPIB round trips per reading instead of two. That is hidden by
; #readingDelay 2; drop that delay for fast logging and it becomes the limit.
#askValues MEAS:VOLT?;MEAS:CURR?;VOLT?;CURR?;STAT:QUES:COND?
#value Voltage V D4
#value Current A D4
#value VoltageSet V D4
#value CurrentSet A D4
#value Regulation - D0
#readingDelay 2

; SYST:REM/SYST:LOC are valid only for RS-232 on this family.
#scpiCmd SerialInit #pgm#
if (portType!="GPIB")
  deviceWrite(handle,"SYST:REM");
endif;

#scpiCmd SerialExit #pgm#
if (portType!="GPIB")
  deviceWrite(handle,"SYST:LOC");
endif;

; SCPIx sends this interface-control token only for a GPIB connection.
#scpiCmd GpibExit
[LOC]

; Quote the user text required by DISP:TEXT while keeping the setup control simple.
#scpiCmd SetDisplayText tx DISP:TEXT "(value)"

#initCmd SerialInit;
#finalCmd OUTP OFF;[*OPC];SerialExit;GpibExit
#outputOff OUTP OFF

; ==============================================================================
; The whole dialog, in the order the supply gets used
; ==============================================================================
; Only the setpoint and pending-setpoint pages differ between the two rows; every
; other page is shared, so the layout does not move when the range changes.

; A single button showing the state it is in, the way the instrument's own output
; key does: grey when off, green when on.
;
; No tag sets a button's size - :labelformat: explicitly excludes buttons and
; :textwidth: only affects input fields - so the button sizes to its label.
; :nogrid: would additionally free it from the form's column grid; it is
; undocumented but used by 55 of the toggleButtons in the shipped drivers. Left
; off so the button aligns with the controls below it, matching the Chroma.
;
; The two labels differ by one character, so the button may shift very slightly as
; it toggles - the docs warn a toggleButton resizes with its label. Padding them to
; equal length only worked by adding a visible character, which was worse.

#cmdSetup toggleButton Output Main
:read: OUTP?
:write: OUTP (value)
:updatedelayed: 0.2
:updatealloff:
:color: gray green
:tip: Enable or disable the DC output. One click toggles it - the button shows the state the output is in now.
OUTPUT_OFF 0
OUTPUT_ON 1

:string:
:updatedelayed: 0.3
:update: Output Voltage Current_Limit Pending_Voltage Pending_Current
:tip: Selects the output range. The Voltage and Current Limit ceilings follow this setting. Changing range always switches the output off first.
