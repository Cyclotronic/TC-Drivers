; HP / Agilent / Keysight E3631A DC Power Supply - TestController driver
;
; Coverage   E3631A triple output: +6 V, +25 V and -25 V
;            Per-channel voltage and current setpoints, the global output
;            enable, tracking mode, trigger coupling, bus and immediate
;            triggering with a delay, stored states, front-panel display text,
;            and a regulation readout per output logged as CC or CV.
;
; Verified   Against an E3631A (firmware 2.1-5.0-1.0) over GPIB. Every setpoint
;            ceiling was read back from the instrument with VOLT? MAX and
;            CURR? MAX and matched the data sheet exactly. Three defects were
;            found on the bench, all of them silent - nothing reaches the error
;            queue for any of them: TestController's automated tools do not
;            switch the output on for a multi-channel driver, *RCL does not
;            restore TRIG:DEL, and a channel re-select landing between INIT and
;            *TRG disarms an armed trigger. The last is worked around by
;            chaining arm and fire into one message; the other two are warned
;            about in the tips beside the controls that hit them. All three are
;            written up in instrument-notes.md beside this file.
;
; Revision   1.2
; Date       2026-08-23

; License    MIT - see LICENSE
;

; TestController by HKJ: https://lygte-info.dk/project/TestControllerIntro%20UK.html

; Multi-channel PS interface. INST:NSEL selects the channel by number
; (1 = P6V, 2 = P25V, 3 = N25V) so the (channel) token maps directly.
; OUTP is global on the E3631A — it controls all three outputs at once.
#interface setVoltage INST:NSEL (channel);VOLT (value)
#interface setCurrent INST:NSEL (channel);CURR (value)
#interface setOn OUTP (value)
#interface getVoltage INST:NSEL (channel);VOLT?
#interface getCurrent INST:NSEL (channel);CURR?
#interface getOn OUTP?
#interface readVoltage 0 2 4
#interface readCurrent 1 3 5
#interface setReadoutString DISP:TEXT ("\""+value+"\"")

; Arm and fire are ONE control here, deliberately. An INST write landing between
; INIT and *TRG disarms the armed trigger and SYST:ERR? stays clean afterwards,
; so nothing surfaces to the operator. This driver issues INST on every logging
; cycle and on every read of this page, which makes that window a real one and
; not a theoretical one. It is cadence-dependent: at a 3 s TestController logging
; interval the armed trigger survived 9 of 9 attempts, and at 0.3 s it was lost
; 2 of 2, with the logging-stopped control leg firing normally both times.
; Bench-confirmed 2026-08-23.
;
; Chaining INIT and *TRG into a single message closes the window - the driver
; cannot interleave inside one write. The cost is that arm-now-fire-later is no
; longer offered from this page, which is the point of a bus trigger; to do that,
; stop logging first and drive INIT and *TRG from a script.
#cmdSetup button Apply_Pending_Values Trigger
:write: INIT;*TRG;*WAI
:updatedelayed: 0.2
:update: Voltage Current Voltage2 Current2 Voltage3 Current3
:tip: Transfer the pending setpoints above to the live outputs. This arms and fires as one chained message because a channel re-select between the two disarms the trigger silently, and this driver issues one on every logging cycle - bench-confirmed lost at a 0.3 s logging interval, survived at 3 s. With Trigger Source set to Immediate the transfer happens on the arm and the trailing *TRG has nothing left to fire; check SYST:ERR? on the Diagnostics page if you use that combination.
